# Lab 01.01 — Understanding Your Computer

## 1. Lab Objective

This lab connects the conceptual model from Chapter 01.01 to the computer you use every day. You will identify the major hardware and software layers, observe how the operating system exposes system resources, and map real system information to the universal input-processing-storage-output model.

By the end of the lab, you should be able to explain your own computer as a layered computing system rather than as a collection of unrelated specifications.

## 2. Expected Outcomes

After completing this lab, you should be able to:

- Identify processor, memory, storage, and network resources.
- Determine the operating system, kernel, and architecture in use.
- Distinguish physical resources from logical resources.
- Observe active processes and resource consumption.
- Identify persistent and volatile storage.
- Trace a simple network request from application input to network output.
- Produce a concise system profile suitable for technical documentation.

## 3. Prerequisites

You need:

- Administrative access is helpful but not mandatory.
- A Windows, Linux, or macOS computer.
- Internet connectivity.
- A terminal or command shell.
- A text editor for recording results.

Do not install additional software unless a step explicitly requires it.

## 4. Lab Safety

This lab is observational. Do not terminate unknown processes, modify firmware settings, delete files, or change network configuration.

## 6. Part B — Inspect Processor Resources

### Windows

```powershell
Get-CimInstance Win32_Processor | Select-Object Name, Manufacturer, NumberOfCores, NumberOfLogicalProcessors, MaxClockSpeed
```

### Linux

```bash
lscpu
```

### macOS

```bash
sysctl -n machdep.cpu.brand_string
```

```bash
sysctl -n hw.physicalcpu
sysctl -n hw.logicalcpu
```

### Questions

1. What is the processor model?
2. How many physical cores are reported?
3. How many logical processors are reported?
4. Why might the logical processor count differ from the physical core count?
5. Is the architecture 32-bit or 64-bit?

## 7. Part C — Inspect Memory

### Windows

```powershell

```

```powershell

```

### Linux

```bash

```

```bash

```

### macOS


### Questions

1. How much physical memory is installed?
2. How much memory is currently available?
3. Which process is consuming the most memory?
4. Is all installed memory available to applications? Explain why or why not.
5. Why is memory considered volatile storage?

### Questions

## 11. Part G — Trace a Simple Network Request

Run the following command:

```bash
curl -I https://example.com
```

In PowerShell, you can also use:

```powershell
Invoke-WebRequest -Method Head https://example.com
```

Record:

- The destination domain
- The returned status code
- Important response headers
- Whether the connection used HTTP or HTTPS

Now determine the resolved IP address.

### Windows

```powershell
Resolve-DnsName example.com
```

### Linux or macOS

```bash
nslookup example.com
```

or:

```bash
dig example.com
```

### Map the request

Describe the request using the following structure:

| Stage | Observation |
|---|---|
| Input | Command or browser action |
| Processing | DNS resolution, TLS, server processing |
| Storage | DNS cache, browser cache, server data |
| Output | HTTP response and rendered content |

## 14. Troubleshooting

### Command not found

Use the command listed for your operating system. Some Linux commands may require packages that are not installed by default. Do not install them unless necessary; use the alternatives provided.

### Permission denied

Run observational commands without elevation first. If a command genuinely requires administrative access, use an elevated PowerShell window or `sudo` only after understanding the command.

### Hardware details appear incomplete

Virtual machines and managed corporate devices may expose only a subset of physical hardware information. Record what the operating system reports and note the limitation.

### Multiple network adapters appear

Virtualization software, VPN clients, container platforms, and security agents commonly create virtual adapters. Distinguish them from the interface providing your active network connection.
