# Lab 01.02 — Computing Evolution Analysis

## 1. Lab Objective

This lab converts the historical evolution of computing into an architecture reasoning exercise. You will compare major computing eras, identify the limitations that drove each transition, and relate those transitions to modern AWS, DevOps, container, and platform engineering concepts.

The purpose is not to memorize dates. The purpose is to understand the recurring engineering pattern:

> A limitation appears, a new abstraction is introduced, and new operational complexity follows.

## 2. Expected Outcomes

After completing this lab, you should be able to:

- Explain why major computing models emerged.
- Compare centralized, client-server, distributed, virtualized, containerized, and serverless models.
- Relate historical resource-sharing models to cloud infrastructure.
- Identify which older concepts remain present in modern architectures.
- Analyze a modern technology through the problem it was created to solve.

## 8. Part F — Centralized vs Distributed Design

Consider an enterprise payroll application.

Design two conceptual versions:

### Version A — Centralized

- One application server
- One database server
- One data center

### Version B — Distributed

- Multiple application instances
- Load balancer
- Replicated database
- Message queue
- Monitoring system
- Multi-zone deployment

For each version, document:

- Availability
- Performance
- Scalability
- Cost
- Operational complexity
- Failure modes
- Data consistency concerns
- Security surface

Conclude which design is more appropriate for:

1. A company with 100 employees.
2. A company with 100,000 employees across several countries.
