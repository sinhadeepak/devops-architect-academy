# Lab 01.07 — Storage Architecture and Persistent Storage Fundamentals

## 1. Lab Objective

This lab connects storage architecture concepts to observable system behavior. You will inspect block devices, partitions, volumes, filesystems, capacity, metadata, I/O patterns, latency, throughput, and storage persistence. You will also evaluate block, file, and object storage choices for production workloads.

## 2. Expected Outcomes

After completing this lab, you should be able to:

- Identify physical and virtual storage devices.
- Explain partitions, volumes, mount points, and filesystems.
- Measure basic sequential and random I/O behavior safely.
- Distinguish latency, throughput, IOPS, and queueing.
- Identify capacity and metadata exhaustion risks.
- Compare block, file, object, and ephemeral storage.
- Design a basic backup and recovery approach.
- Produce a structured storage investigation report.

## 3. Safety

Use only temporary files in a directory you own. Do not benchmark production disks, shared enterprise storage, database volumes, Kubernetes persistent volumes, or cloud resources without authorization. Do not use destructive disk-management commands.

## 9. Part F — Sequential Write Test

Create `sequential_write.py`:

```python
from pathlib import Path
import os
import time

path = Path("storage-lab/sequential.bin")
chunk = os.urandom(1024 * 1024)
iterations = 128

started = time.perf_counter()
with path.open("wb", buffering=0) as file:
    for _ in range(iterations):
        file.write(chunk)
    file.flush()
    os.fsync(file.fileno())
elapsed = time.perf_counter() - started
size_mib = iterations

print(f"size_mib={size_mib}")
print(f"elapsed_seconds={elapsed:.3f}")
print(f"throughput_mib_s={size_mib / elapsed:.2f}")
```

Run it in the temporary directory.

Record:

- File size
- Elapsed time
- Approximate throughput
- Storage type
- Whether caching may affect the result

This is an observation exercise, not a certified benchmark.

## 10. Part G — Random Access Test

Create `random_access.py`:

```python
from pathlib import Path
import os
import random
import time

path = Path("storage-lab/random.bin")
file_size = 64 * 1024 * 1024
block_size = 4096
operations = 5000

with path.open("wb") as file:
    file.truncate(file_size)

with path.open("r+b", buffering=0) as file:
    started = time.perf_counter()
    for _ in range(operations):
        offset = random.randrange(0, file_size // block_size) * block_size
        file.seek(offset)
        file.write(os.urandom(block_size))
    file.flush()
    os.fsync(file.fileno())
    elapsed = time.perf_counter() - started

print(f"operations={operations}")
print(f"elapsed_seconds={elapsed:.3f}")
print(f"approx_iops={operations / elapsed:.2f}")
print(f"average_latency_ms={(elapsed / operations) * 1000:.3f}")
```

Compare the result with the sequential test.

Explain why random I/O and sequential I/O stress storage differently.

## 12. Part I — Cache Effects

Run the sequential read of the same test file twice.

Create `sequential_read.py`:

```python
from pathlib import Path
import time

path = Path("storage-lab/sequential.bin")

for run in range(1, 3):
    started = time.perf_counter()
    total = 0
    with path.open("rb") as file:
        while chunk := file.read(1024 * 1024):
            total += len(chunk)
    elapsed = time.perf_counter() - started
    print(run, total, elapsed)
```

Answer:

1. Was the second read faster?
2. Could the operating-system cache explain the difference?
3. Why should cache state be documented in benchmark results?
