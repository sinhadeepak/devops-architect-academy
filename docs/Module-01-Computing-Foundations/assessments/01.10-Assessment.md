# Assessment 01.10 — Operating System Architecture

## 1. Purpose

This assessment verifies that you can reason about operating-system architecture rather than merely identify commands. You should be able to explain kernel and user-space boundaries, processes, threads, scheduling, system calls, signals, descriptors, inter-process communication, services, resource limits, containers, and operating-system troubleshooting.

## 2. Mastery Requirement

The required mastery score is **95%**.

| Dimension | Weight |

| Kernel and operating-system architecture | 25% |
| Processes, threads, scheduling, and IPC | 25% |
| Containers, security, and resource governance | 25% |
| Troubleshooting and architecture reasoning | 25% |

## 18. Section P — Operating-System Bottleneck Scenarios

For each scenario, identify likely causes, evidence, immediate mitigation, root-cause remediation, and validation steps.

### Scenario 1 — High Load, Low CPU

Load average is high, aggregate CPU is low, and many tasks are in uninterruptible sleep.

### Scenario 2 — High System CPU

System CPU is high, application user CPU is low, and network throughput is elevated.

### Scenario 3 — Descriptor Exhaustion

A service cannot accept new connections and reports `too many open files`.

### Scenario 4 — Restart Loop

A service supervisor restarts a process every few seconds.

### Scenario 5 — Container Force-Killed

A container consistently ignores `SIGTERM` and reaches forced termination.

### Scenario 6 — Thread Explosion

A service has thousands of threads, high context switching, and low throughput.

### Scenario 7 — Lock Wait

A process is alive but makes no progress because it is blocked on a lock.

### Scenario 8 — Process Exhaustion

A host cannot create new processes or threads.

### Scenario 9 — High User CPU

Application user CPU is near 100% while system CPU remains moderate.

### Scenario 10 — Kernel or Driver Failure

Several unrelated applications fail after a new kernel module is loaded.
