# Assessment 01.06 — Memory Architecture and Memory Management

## 1. Purpose

This assessment verifies that you understand how operating systems, virtual machines, containers, and cloud platforms allocate, translate, cache, reclaim, limit, and exhaust memory.

The objective is not to memorize metric names. You should be able to distinguish normal memory use from pressure, identify whether a problem is caused by sizing, leakage, caching, garbage collection, swapping, or platform limits, and select an appropriate remediation.

## 18. Section P — Troubleshooting Scenarios

For each scenario, identify likely causes, required evidence, immediate mitigation, and long-term remediation.

### Scenario 1 — Continuous Growth

Resident memory grows after every traffic burst and never stabilizes.

### Scenario 2 — Healthy Cache

Memory grows to a fixed level, stabilizes, and application hit rate improves.

### Scenario 3 — Swap Thrashing

The system shows heavy swap activity, high storage latency, and low useful throughput.

### Scenario 4 — Frequent GC Pauses

A service remains below its memory limit but experiences repeated latency spikes.

### Scenario 5 — Container OOM

A container is `OOMKilled`, while the Kubernetes node still has available memory.

### Scenario 6 — Node Pressure

Several pods are evicted from a node even though none exceeded its individual limit.

### Scenario 7 — VM Host Contention

Multiple virtual machines slow down simultaneously during host memory pressure.

### Scenario 8 — Oversized Request

A pod requests 8 GiB but normally uses 1.5 GiB, causing scheduling failures.

## 19. Section Q — Architect's Memory Review

- Peak working set: 1.95 GiB
- Frequent full garbage collections
- Two `OOMKilled` restarts during traffic peaks
- Node memory remains healthy

Document:

1. Most likely causes
2. Evidence supporting each hypothesis
3. Immediate mitigation
4. Recommended request
5. Recommended limit
6. Heap or runtime changes
7. Application-level investigation
8. Risk of only increasing the limit
9. Monitoring improvements
10. Validation plan after remediation
