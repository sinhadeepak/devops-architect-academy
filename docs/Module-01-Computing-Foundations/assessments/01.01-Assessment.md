# Assessment 01.01 — Introduction to Modern Computing

## 1. Purpose

This assessment verifies whether you have developed the foundational mental model required for the remainder of the DevOps Architect Academy.

The objective is not memorization. You should be able to explain computing concepts in your own words, relate them to real systems, and apply them to cloud and DevOps scenarios.

## 2. Mastery Requirement

The required mastery score is **95%**.

To pass, you must demonstrate competence in all four dimensions:

| Dimension | Weight |
|---|---:|
| Conceptual understanding | 30% |
| Practical system understanding | 25% |
| Troubleshooting reasoning | 20% |
| Architectural application | 25% |

A high total score cannot compensate for a major gap in one dimension. Any dimension below 80% requires revision.

## 3. Section A — Core Concepts

Answer each question in your own words.

### Question 1

Define computing from an engineering perspective.

### Question 2

Explain the difference between data, information, and instructions. Provide one example of each.

### Question 3

Describe the four universal functions of a computing system.

### Question 4

Explain why the network is often the primary input and output mechanism for cloud systems.

### Question 5

What is the difference between volatile and persistent storage? Give at least three examples of each.

### Question 6

Differentiate hardware, firmware, an operating system, a runtime, middleware, and an application.

### Question 7

Why is abstraction useful in computing?

### Question 8

What does it mean when an abstraction leaks? Give one infrastructure example.

### Question 9

Explain the difference between concurrency and parallelism.

### Question 10

Explain the difference between stateful and stateless components.

## 4. Section B — Applied Understanding

### Question 11

A user opens a web application and submits a login form. Map the interaction to:

- Input
- Processing
- Storage
- Output

### Question 12

Explain how the following local computer components approximately map to AWS services:

- Processor and memory
- Local block storage
- Shared file storage
- Network interface
- Firewall controls
- Operating system image

### Question 13

A server has 16 physical CPU cores but reports 32 logical processors. Explain why this may occur.

### Question 14

A system has 32 GB of RAM, but the operating system reports less than 32 GB available to applications. Explain at least three possible reasons.

### Question 15

A managed database is provided as a cloud service. Identify which computing fundamentals still exist beneath the managed abstraction.

## 5. Section C — Troubleshooting Reasoning

### Scenario 1 — Slow Application

An application becomes slow during peak traffic. CPU utilization is only 35%.

Explain why adding more CPU may not solve the problem. Identify at least five alternative bottlenecks.

### Scenario 2 — Memory Pressure

A service gradually consumes more memory and eventually restarts.

Describe:

1. The symptoms you would expect.
2. The likely difference between a memory leak and normal caching.
3. The information you would collect before changing the system.
4. The risks of simply increasing available memory.

### Scenario 3 — Storage Saturation

A database server shows low CPU utilization but poor response times. Disk latency is very high.

Explain the likely relationship between storage performance and application latency.

### Scenario 4 — Network Dependency Failure

A web application is running, but users cannot log in because the identity provider is unavailable.

Explain why the application can be technically healthy while the user-facing service remains unavailable.

### Scenario 5 — Cloud Misconception

A team claims that moving to the cloud eliminates infrastructure failures.

Evaluate this statement and explain how responsibility changes rather than disappears.

## 6. Section D — Architectural Application

### Question 16

List and define the following quality attributes:

- Performance
- Reliability
- Availability
- Scalability
- Security
- Maintainability
- Resilience
- Cost efficiency

### Question 17

Why can optimizing one quality attribute negatively affect another? Provide two examples.

### Question 18

For a new enterprise application, explain how you would determine whether a component should be stateful or stateless.

### Question 19

Using the Architect's Mental Model, analyze a CI/CD runner by answering:

1. What problem does it solve?
2. What inputs does it accept?
3. What processing does it perform?
4. What state does it maintain?
5. What outputs does it produce?
6. What resources does it consume?
7. What are its primary failure modes?
8. What security boundaries exist?
9. How can it scale?
10. How should it be monitored?

### Question 20

Explain why a DevOps Architect must understand both high-level cloud services and low-level computing fundamentals.

## 7. Section E — Practical Evidence

Submit your completed `my-system-profile.md` from Lab 01.01.

The profile must include:

- Operating system and kernel
- Processor model and architecture
- Physical and logical processor counts
- Installed and available memory
- Storage devices and filesystems
- Active network interface and gateway
- Examples of input, processing, storage, and output
- Three observations about system behavior

## 8. Section F — Oral Explanation Exercise

Explain the following scenario without referring to notes:

> A user enters a URL in a browser and receives a webpage from an application hosted in AWS.

Your explanation should cover:

- User input
- DNS resolution
- Network communication
- TLS
- Load balancing
- Application processing
- Database or cache access
- Storage
- Response generation
- Browser rendering
- Monitoring and logging

A strong answer should clearly distinguish the physical, operating-system, network, application, and cloud-service layers.

## 10. Answer Guidance

Use the following principles when evaluating responses:

- Answers should demonstrate understanding rather than repeat chapter wording.
- Examples must be technically relevant.
- Troubleshooting answers should identify evidence to collect before proposing changes.
- Architecture answers should discuss trade-offs rather than presenting one universal solution.
- Cloud answers should preserve the connection to physical computing resources.
