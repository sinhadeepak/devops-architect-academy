# Assessment 01.09 — BIOS, UEFI, Boot Process, Secure Boot, and Kernel Startup

## 1. Purpose

This assessment verifies that you understand how a computer moves from power-on to a running operating system and application-ready state.

You should be able to identify each boot stage, explain the trust chain, distinguish firmware, bootloader, kernel, early user space, and service startup, and diagnose failures using evidence from the correct layer.

## 21. Section S — Troubleshooting Scenarios

For each scenario, identify the failed stage, evidence required, safe immediate action, long-term remediation, and prevention.

### Scenario 1 — Hardware Diagnostic Failure

The machine powers on but produces no operating-system output and shows a hardware diagnostic code.

### Scenario 2 — Missing Boot Device

Firmware detects the storage controller but reports no bootable target.

### Scenario 3 — Secure Boot Rejection

A third-party kernel module or bootloader update is rejected after reboot.

### Scenario 4 — Kernel Not Found

The bootloader menu is available, but the selected kernel image cannot be loaded.

### Scenario 5 — Root Filesystem Unavailable

The kernel loads but cannot locate or mount the root filesystem.

### Scenario 6 — Failed Required Mount

The operating system enters emergency mode after a storage configuration change.

### Scenario 7 — Cloud Image Failure

A new VM image starts, but no network interface becomes usable and remote access is impossible.

### Scenario 8 — Cloud-Init Failure

The VM completes operating-system startup but user creation, keys, and application initialization fail.

### Scenario 9 — Kubernetes Node NotReady

The operating system and kubelet are running, but the node remains unavailable for workloads.

### Scenario 10 — Encryption Recovery

A firmware update causes a disk-encryption recovery prompt across a fleet.
