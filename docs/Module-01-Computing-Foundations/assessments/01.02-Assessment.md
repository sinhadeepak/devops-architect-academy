# Assessment 01.02 — The Evolution of Computing

## 1. Purpose

This assessment verifies that you understand the evolution of computing as a sequence of engineering responses to earlier limitations.

The objective is not to memorize dates or names. You should be able to explain why each major computing model emerged, what problem it solved, what abstraction it introduced, and what new complexity followed.

## 2. Mastery Requirement

The required mastery score is **95%**.

Assessment dimensions:

| Dimension | Weight |
|---|---:|
| Historical and conceptual understanding | 25% |
| Architectural transition reasoning | 30% |
| Modern cloud and DevOps mapping | 25% |
| Trade-off and failure analysis | 20% |

Any dimension below 80% requires revision, even when the overall score exceeds 95%.

## 6. Section D — Trade-Off Analysis

### Scenario 1 — Bare Metal vs Virtual Machines

An enterprise runs a latency-sensitive trading application.

Compare bare-metal servers and virtual machines using:

- Performance
- Isolation
- Provisioning speed
- Operational flexibility
- Cost
- Failure recovery

Conclude which model is more appropriate and justify the decision.

### Scenario 2 — Virtual Machines vs Containers

A company has 100 independently deployable web services.

Compare virtual machines and containers using:

- Startup time
- Resource efficiency
- Isolation
- Portability
- Operational complexity
- Security

### Scenario 3 — Kubernetes vs Managed Platform

A team wants Kubernetes because it is widely used, but the application consists of three low-traffic services.

Evaluate whether Kubernetes is justified.

### Scenario 4 — Serverless vs Long-Running Service

A workload processes one short event every few minutes. Compare a serverless function with a continuously running virtual machine.

### Scenario 5 — Centralized vs Distributed Architecture

A payroll application serves 500 employees in one country. Evaluate whether a distributed microservices architecture is necessary.
