# Module 01 — Computing Foundations

# Chapter 01.01 — Introduction to Modern Computing

## 1. Purpose of This Chapter

Every cloud platform, Kubernetes cluster, CI/CD pipeline, database, mobile application, artificial intelligence workload, and enterprise system ultimately runs on computing infrastructure.

Engineers frequently learn tools before learning the systems beneath those tools. This creates fragmented knowledge: they can deploy a workload but may not understand why it slows down, why it fails under load, why memory pressure causes instability, or why a network request behaves differently across environments.

This chapter establishes the base mental model for the entire DevOps Architect Academy. It explains what computing is, why computers exist, how every computer performs the same four fundamental functions, how the major software and hardware layers relate to one another, and how these concepts extend naturally into cloud architecture.

## 2. Learning Objectives

After completing this chapter, you should be able to:

- Define computing from an engineering perspective.
- Explain why computers were created and what problems they solve.
- Describe the input, processing, storage, and output model.
- Distinguish data from information and instructions from execution.
- Differentiate hardware, firmware, operating systems, and applications.
- Explain how a request moves through a modern computing environment.
- Relate traditional computing concepts to AWS, containers, and DevOps.
- Identify the primary quality attributes used to evaluate computing systems.

## 3. What Is Computing?

Computing is the controlled transformation of data through programmable instructions.

A computing system receives data, performs operations on that data, stores intermediate or final results, and produces an output. The operations may be simple, such as adding two numbers, or highly complex, such as training a machine learning model across thousands of processors.

A useful engineering definition is:

> Computing is the execution of instructions by a programmable system to transform input data into useful output while managing state, resources, and communication.

This definition introduces five important ideas:

1. **Instructions** define what work must be performed.
2. **Data** is the material being processed.
3. **Execution** is the actual performance of instructions.
4. **State** represents information that persists during or after execution.
5. **Resources** include processor time, memory, storage, and network capacity.

## 4. Why Computers Were Invented

Computers emerged because human societies required faster, more accurate, more repeatable ways to process information.

### 4.1 Speed

Humans can perform calculations, but computers can execute billions of operations per second. This makes them suitable for simulations, financial processing, analytics, graphics, and automation.

### 4.2 Accuracy

A computer follows its instructions exactly. When software and hardware operate correctly, the same input and instructions produce consistent results.

### 4.3 Automation

Computers can repeat defined procedures without fatigue. Automation is the foundation of modern DevOps, where builds, tests, deployments, backups, scaling, and monitoring are performed continuously.

### 4.4 Storage

Computers can retain large volumes of information and retrieve it rapidly. Storage systems allow organizations to preserve transactions, documents, logs, configurations, images, and application state.

### 4.5 Communication

Networked computers exchange information across local and global distances. Modern business systems depend on this communication for APIs, messaging, collaboration, cloud services, and distributed applications.

## 5. The Universal Computing Model

Every computing system performs four fundamental functions:

1. Input
2. Processing
3. Storage
4. Output

![Figure 01.01 — Universal Computing Model](assets/01.01-fig-01-universal-computing-model.png)

### 5.1 Input

Input is the reception of data or instructions from outside the current processing context.

Common human input mechanisms include:

- Keyboard
- Mouse
- Touch screen
- Microphone
- Camera

Common machine input mechanisms include:

- Network packets
- API requests
- Sensors
- Files
- Message queues
- Database queries

For cloud systems, the network is usually the most important input channel.

### 5.2 Processing

Processing transforms input according to instructions. The central processing unit normally performs general-purpose processing, while specialized processors may handle graphics, machine learning, encryption, or signal processing.

Typical processing operations include:

- Arithmetic calculations
- Logical comparisons
- Data validation
- Searching and sorting
- Encryption and decryption
- Compression
- Image transformation
- Business-rule evaluation

### 5.3 Storage

Storage preserves data for immediate or future use.

Storage exists at multiple levels:

- CPU registers
- Processor cache
- Main memory
- Local persistent storage
- Network-attached storage
- Distributed object storage
- Databases

Some storage is volatile and loses data when power is removed. Other storage is persistent and retains data across restarts.

### 5.4 Output

Output is the result produced by the computing system.

Examples include:

- A screen display
- A printed document
- An API response
- A database update
- A network packet
- A generated report
- A physical action by a robot or actuator

In cloud computing, output is commonly delivered as a network response or an event.

## 6. Data, Information, and Instructions

These terms are related but not identical.

### 6.1 Data

Data is a raw representation of facts, measurements, symbols, or events.

Examples:

- `42`
- `2026-08-01`
- A temperature reading
- A customer identifier
- A network packet

### 6.2 Information

Information is data interpreted within a context.

For example, `42` becomes meaningful when interpreted as:

- 42 requests per second
- 42 degrees Celsius
- 42 failed builds
- Customer number 42

### 6.3 Instructions

Instructions specify what operations the system should perform. Software is ultimately composed of instructions represented in a form the processor can execute.

A program combines instructions and data to produce behavior.

## 7. Hardware and Software Layers

A modern computing system is organized into layers. Each layer abstracts the complexity of the layer below it.

![Figure 01.02 — Modern Computing Stack](assets/01.01-fig-02-modern-computing-stack.png)

### 7.1 Hardware

Hardware consists of physical components such as:

- Processor
- Memory
- Storage devices
- Motherboard
- Network interface
- Input and output devices

### 7.2 Firmware

Firmware is low-level software stored close to the hardware. It initializes devices and provides basic control mechanisms.

Examples include:

- BIOS
- UEFI
- Device firmware
- Embedded controller firmware

### 7.3 Operating System

The operating system manages hardware resources and provides common services to applications.

Its responsibilities include:

- Process scheduling
- Memory management
- File management
- Device access
- Networking
- Security boundaries
- User management

### 7.4 Runtime and Middleware

Runtimes and middleware provide reusable services above the operating system.

Examples include:

- Java Virtual Machine
- .NET runtime
- Node.js runtime
- Web servers
- Application servers
- Message brokers
- Database engines

### 7.5 Applications

Applications implement user-facing or business-facing functionality.

Examples include:

- Web applications
- Mobile applications
- Banking systems
- Monitoring platforms
- CI/CD tools
- Infrastructure automation systems

## 8. How a Modern Request Is Processed

Consider a user opening an e-commerce website.

1. The browser accepts the user's input.
2. The operating system sends a DNS request.
3. The domain name is translated into an IP address.
4. The browser establishes a network connection.
5. An HTTPS request reaches a load balancer.
6. The load balancer forwards the request to an application instance.
7. The application reads data from a database or cache.
8. Static assets may be retrieved from object storage or a content delivery network.
9. The application produces a response.
10. The response travels back to the browser and is rendered on the screen.

![Figure 01.03 — End-to-End Web Request Lifecycle](assets/01.01-fig-03-web-request-lifecycle.png)

The user experiences one page load, but many computers and software layers cooperate to produce it.

## 9. Types of Computing Systems

### 9.1 Personal Computers

Designed primarily for individual productivity and general-purpose use.

### 9.2 Servers

Designed to provide shared services to many users or systems. Servers commonly host applications, databases, storage, and network services.

### 9.3 Embedded Systems

Integrated into larger devices and optimized for specific functions. Examples include automotive controllers, routers, industrial devices, and medical equipment.

### 9.4 Mobile Systems

Designed for portability, battery efficiency, wireless communication, and sensor-rich interaction.

### 9.5 Mainframes

Optimized for large-scale transaction processing, reliability, and centralized enterprise workloads.

### 9.6 Supercomputers

Designed for highly parallel scientific and engineering computations.

### 9.7 Cloud Infrastructure

Cloud infrastructure pools computing resources and exposes them as on-demand services. Users consume virtual machines, containers, storage, databases, and networking without owning the underlying physical hardware.

### 9.8 Edge Systems

Edge systems process data near the source of generation to reduce latency, bandwidth usage, or dependency on centralized infrastructure.

## 10. Traditional Computing and Cloud Computing

Cloud computing is not a replacement for computing fundamentals. It is a service-delivery model built upon those fundamentals.

A virtual machine still requires:

- Processing capacity
- Memory
- Storage
- Networking
- An operating system

A managed database still depends on processors, memory, storage engines, network communication, replication, and operating-system services.

The key difference is operational ownership.

| Area | Traditional Infrastructure | Cloud Infrastructure |
|---|---|---|
| Hardware ownership | Customer | Cloud provider |
| Capacity procurement | Planned and purchased | Requested on demand |
| Scaling | Often manual and slow | Potentially automated and rapid |
| Pricing | Capital expenditure | Usage-based operating expenditure |
| Physical maintenance | Customer responsibility | Provider responsibility |
| Service abstraction | Limited | Extensive managed services |

## 11. Computing and DevOps

DevOps is an engineering approach for improving the speed, reliability, and safety of software delivery and operations.

DevOps tools are built on computing fundamentals:

- Git stores and transfers data.
- Build systems consume processor and memory resources.
- CI/CD runners execute operating-system processes.
- Containers isolate applications through operating-system mechanisms.
- Kubernetes schedules workloads across computers.
- Monitoring tools collect and store telemetry.
- Infrastructure as Code converts desired state into infrastructure changes.

A DevOps Architect must understand both the abstraction and the underlying system.

## 12. Core Quality Attributes of Computing Systems

Architects evaluate computing systems using quality attributes rather than features alone.

### 12.1 Performance

Performance describes how efficiently a system completes work.

Important measurements include:

- Latency
- Throughput
- Processor utilization
- Memory utilization
- Storage input/output operations
- Network bandwidth

### 12.2 Reliability

Reliability is the probability that a system performs correctly over a defined period.

### 12.3 Availability

Availability is the proportion of time the system is usable.

### 12.4 Scalability

Scalability is the ability to handle increased demand by adding or improving resources.

### 12.5 Security

Security protects confidentiality, integrity, and availability.

### 12.6 Maintainability

Maintainability describes how easily the system can be updated, repaired, monitored, and extended.

### 12.7 Resilience

Resilience is the ability to withstand failures and recover without unacceptable impact.

### 12.8 Cost Efficiency

Cost efficiency is the ability to deliver required outcomes without unnecessary resource consumption or expenditure.

## 13. Abstraction in Computing

Abstraction hides lower-level complexity behind simpler interfaces.

Examples include:

- Applications use files without controlling disk sectors directly.
- Containers use virtual networks without managing physical switch hardware.
- AWS users create EC2 instances without installing physical servers.
- Developers call APIs without needing to know every internal implementation detail.

Abstraction increases productivity, but architects must understand where abstractions can leak. Performance issues, security boundaries, failures, and cost behavior often require knowledge of the underlying layers.

## 14. State and Statelessness

State is information that must be retained across operations.

A stateful system remembers previous interactions. A stateless system treats each request independently.

Examples of state include:

- User sessions
- Database records
- Files
- Queue messages
- Infrastructure configuration

Stateless application components are generally easier to scale and replace. Stateful components require careful design for persistence, replication, recovery, and consistency.

## 15. Concurrency and Parallelism

Concurrency means multiple tasks make progress during overlapping periods. Parallelism means multiple tasks execute at the same time on separate processing resources.

These concepts influence:

- Web server capacity
- Database performance
- Build pipelines
- Container scheduling
- Distributed systems
- Batch processing

They will be explored in detail in later chapters on processors, operating systems, and distributed systems.

## 16. Failure Is Normal

Modern computing systems are complex, and failures are inevitable.

Possible failures include:

- Hardware malfunction
- Software defects
- Network interruption
- Resource exhaustion
- Misconfiguration
- Security compromise
- Dependency outage
- Human error

Architectural maturity is not defined by eliminating every failure. It is defined by detecting, containing, recovering from, and learning from failures.

## 17. Production Perspective

A production-grade computing system must answer the following questions:

- What happens when demand doubles?
- What happens when one component fails?
- How is data protected?
- How is access controlled?
- How is the system monitored?
- How are changes deployed safely?
- How quickly can the system recover?
- What does the system cost to operate?

These questions will recur throughout the academy.

## 18. Common Misconceptions

### Misconception 1: Cloud computing is unrelated to physical hardware

Cloud services are implemented on physical computers, networks, and storage systems managed by a provider.

### Misconception 2: More CPU always solves performance problems

A system may be limited by memory, storage, networking, locking, inefficient queries, or application design.

### Misconception 3: DevOps is a collection of tools

Tools support DevOps practices, but the discipline concerns software delivery, automation, feedback, reliability, and collaboration.

### Misconception 4: Managed services eliminate operational responsibility

Managed services reduce certain responsibilities, but customers still own architecture, configuration, access control, data protection, monitoring, and cost management.

## 19. Architect's Mental Model

When evaluating any technology, ask:

1. What problem does it solve?
2. What inputs does it accept?
3. What processing does it perform?
4. What state does it maintain?
5. What outputs does it produce?
6. What resources does it consume?
7. What are its failure modes?
8. What security boundaries exist?
9. How does it scale?
10. How is it monitored and operated?

This framework applies to computers, applications, AWS services, Kubernetes components, CI/CD systems, and enterprise platforms.

## 20. Chapter Summary

- Computing transforms input data into output through programmable instructions.
- Every computing system performs input, processing, storage, and output functions.
- Hardware, firmware, operating systems, runtimes, and applications form layered abstractions.
- Cloud computing delivers traditional computing capabilities as on-demand services.
- DevOps tools operate on the same underlying processor, memory, storage, network, and operating-system foundations.
- Architects evaluate systems through quality attributes such as performance, reliability, availability, scalability, security, maintainability, resilience, and cost efficiency.
- Strong architecture requires understanding both abstractions and the systems beneath them.
